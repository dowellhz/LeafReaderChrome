# LeafReader Chrome 产品需求

## 1. 产品范围

LeafReader Chrome 是一个 Manifest V3 Chrome 扩展，将 LeafReader 的网页阅读、选词辅助、笔记、生词、朗读和可选 AI 能力带到普通网页。

- 支持 `http`、`https` 网页。
- PDF、EPUB、DOCX 不在本项目范围内。
- 产品以中文优先；界面语言可跟随 Chrome，也可切换为中文或英文。
- 右侧能力必须使用 Chrome 原生 Side Panel，不得在网页内伪造右侧悬浮窗口。

## 2. 网页选词与浮动菜单

用户在普通网页中选中文本后，扩展应显示不干扰选区的浮动菜单。菜单包含：

- 翻译
- 词典
- 保存单词
- 高亮
- 笔记
- 朗读
- AI 讲解

要求：

- 菜单不应阻碍浏览器原生选词、复制或页面点击。
- 支持鼠标、双击和键盘扩展选区。
- 首次点击 AI、翻译或词典时应立即打开原生侧边栏，并立刻显示加载状态。
- 词典只面向单词或短语；超过 160 字符的选择应自动改为完整翻译。
- 翻译必须要求模型按顺序完整翻译所选文本，不得以摘要替代。

## 3. 原网页标记

翻译、词典、AI 讲解、高亮和笔记创建的内容应能在原网页中留下持久标记。

- 使用 CSS Custom Highlight API，不使用包裹原网页文本的 DOM 节点。
- 标记记录保存原文、上下文、页面 URL、标题和可靠文本锚点。
- 文本锚点需包含精确文本、前后缀和位置；页面刷新或部分动态更新后应尽力恢复。
- 点击带 AI 内容的标记时，必须打开原生侧边栏，恢复该页面对应的会话，并滚动到该标记对应的回答位置。
- 点击高亮或笔记时，应打开与该记录相关的侧边栏内容或阅读记录。
- 页面内容观察应节流并在空闲时恢复标记，不能因字符级 DOM 变化频繁重建全文索引。

## 4. 原生侧边栏

侧边栏是选词结果和网页 AI 阅读轨迹的唯一右侧展示区域。

- 每个网页以完整 `web:<URL>` 为作用域；切换 URL 时不得显示其他网页的内容。
- 同一网页内，翻译、词典、AI 讲解可组成可滚动的结果轨迹。
- 新结果显示后应滚动到该结果的回答区域，而不是停留在顶部或旧位置。
- 从网页标记恢复时应定位到关联结果；普通回到同一网页时应恢复用户此前的滚动位置。
- 追问输入框始终显示在有会话的结果底部；点击发送后应立即显示用户消息和 Thinking 加载指示，再请求 AI。
- 追问完成后滚动到底部；失败时保留问题并显示可读错误，允许重试。
- 词典首答不重复显示与“所选文本”相同的 `YOU` 气泡，内容应紧凑。
- 支持导出和清空当前会话，以及查看会话历史。
- 页面导航时清除陈旧的临时侧栏 payload，但不要反复禁用/启用 Side Panel。

## 5. Side Panel API 约束

- 通过浮动菜单的 `pointerdown` 用户手势触发打开。
- 后台必须以 `chrome.sidePanel.open({ tabId: sender.tab.id })` 打开。
- 不得改用 `windowId`，否则部分 Chrome 版本会丢失用户手势。
- 调用标签页 API 前必须验证 tab id；导航后的迟到消息不能导致异常。
- 不得出现 `No active side panel for tabId`、重复 context-menu id 或扩展上下文失效导致的未捕获错误。

## 6. AI 设置与供应商

AI 是可选能力。设置页提供：界面语言、供应商、endpoint、模型、API key、阅读字体，以及“保存设置”和“测试 AI 连接”。

支持供应商：

- OpenAI
- DeepSeek（Flash、Pro）
- OpenRouter
- 通义千问 DashScope
- Groq
- SiliconFlow
- Anthropic Claude
- Google Gemini
- Ollama
- Azure OpenAI
- 自定义 OpenAI 兼容接口

要求：

- 根据供应商构造正确端点和请求体；Anthropic、Gemini、Ollama、Azure 不能被当作普通 OpenAI URL 重写。
- 测试连接使用一次最小请求，并显示成功、HTTP 失败、不可连接或响应格式不匹配的可读信息。
- AI 回复语言按设置决定；“自动”读取 Chrome 当前 UI 语言。
- 普通回答目标上限为 2200 tokens，完整翻译目标上限为 4000 tokens；供应商报告长度截断时应明确提示。
- API key 仅保存在 Chrome 本地扩展存储中，只发送到用户配置的供应商；不得写入日志、代码、测试、备份（除非用户明确勾选包含）。

## 7. 词典、生词与朗读

- 单词词典优先使用已配置 AI 生成中文语境释义、发音、常见用法和词性；AI 不可用时可提供明确标识的英文词典兜底。
- 同一词形按 lemma 合并，记录出现次数、页面、上下文、释义和复习状态。
- 生词支持间隔重复复习相关字段。
- 朗读使用浏览器 `speechSynthesis`；根据文本选择中文或英文语言，并使用浏览器可用声音。不得承诺第三方高质量音色。

## 8. 阅读器与资料库

- 可将当前网页提取到独立阅读器。
- 阅读器支持本地资料库、阅读进度、搜索、字体排版、明暗主题、逐句朗读、笔记、生词和来源跳转。
- 捕获网页正文保存在 IndexedDB；不得把网页正文强制发送给 AI。
- 页面无法提取时，向用户显示可读失败提示。

## 9. 数据模型、同步与备份

- 设置、标记、生词使用 `chrome.storage.local`。
- 标记和生词的新增、更新、删除必须经过 Service Worker 串行写入；内容脚本、阅读器和侧边栏不得分别进行全数组读—改—写。
- 会话按 `leafreader:panel:conversation:<id>` 存储，网页轨迹按 `leafreader:panel:thread:<encoded-document-id>` 存储，避免重写巨大全局对象。
- 应自动迁移旧的 `aiConversations` 和 `sidePanelThreads` 数据。
- 备份格式为 `leafreaderchrome-backup`，当前版本为 v2；导入需兼容 v1，校验格式、必要数组、对象字段和 50 MB 大小上限。
- 备份导出包含网页、标记、生词、会话和页面轨迹；默认排除 API key。
- 为长时间阅读数据申请 `unlimitedStorage`。

## 10. 性能、稳定性与视觉要求

- 选词和原网页标记不应明显影响网页的选择、滚动或交互。
- 侧边栏渲染同一网页的多个会话时应批量读取会话，避免每条记录单独读取存储。
- 侧边栏应滚动实际拥有 `overflow` 的容器；原生 Side Panel 布局完成后需要再次校正目标位置。
- 设置页必须加载共享主题 CSS 后再加载设置页 CSS，保证颜色变量、输入框、按钮和边框样式完整。
- Markdown 结果须正确渲染标题、段落、列表、代码和表格；不能把原始 Markdown 直接展示为纯文本。
- 所有用户可见错误需要易理解，避免只显示未捕获异常或无上下文的“没有反应”。

## 11. 开发与发布质量门槛

- 任一源代码文件不得超过 500 行；超出前必须按职责拆分，不能通过压缩代码规避。
- 每个用户可见扩展修改都递增 `manifest.json` patch version，并保持与 `package.json` 一致。
- 保留 LeafReader 图标的 16、32、48、128 像素清单配置。
- JavaScript 改动至少运行 `npm run check` 和 `npm test`。
- 发布前运行 `npm run smoke:chrome`，它必须使用 `/private/tmp` 下隔离的 Chrome profile，不能触碰日常浏览器数据。
- 手动验收至少覆盖：选词菜单、首次打开侧栏、加载状态、AI 结果、追问、原网页标记、点击标记定位、刷新恢复、跨 URL 隔离、设置页样式、服务工作线程错误页。

## 12. 验收场景

1. 在网页选中一个英文单词，点击词典：侧栏立即打开，显示加载，再显示紧凑的中文释义；网页留下可点击标记。
2. 在网页选中一段文字，点击翻译：侧栏显示完整翻译，定位到该条结果；刷新网页后标记仍能恢复。
3. 点击旧翻译标记：侧栏打开同 URL 轨迹，自动滚到该翻译回答，而非顶部或最后一条无关结果。
4. 在侧栏追问：立即显示问题与 Thinking，完成后滚到末尾；切换到另一 URL 不显示这段对话。
5. 多个页面同时添加标记或生词：不丢失任一记录。
6. 打开设置页：所有选择框、输入框和按钮均按主题完整显示；测试连接给出明确结果。
7. 导出 v2 备份后导入；导入 v1 备份；两者均保留网页、标记、生词和会话数据。
